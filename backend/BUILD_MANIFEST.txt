   Routes → Controllers → Services → Repositories → Models

##  ARCHITECTURE PRINCIPLES IMPLEMENTED

 Separation of Concerns
   • Each layer has exactly one responsibility
   • Routes define endpoints, controllers parse requests, services contain logic

 DRY (Don't Repeat Yourself)
   • Shared utilities (asyncHandler, AppError, dateHelpers)
   • Repositories abstract data access patterns

 SOLID Principles
   • Single Responsibility: Each class/function does one thing
   • Open/Closed: AI provider interface allows extension without modification
   • Liskov Substitution: AI providers are interchangeable
   • Interface Segregation: Lean, focused interfaces
   • Dependency Inversion: Services depend on abstractions

 Fail-Safe Design
   • AI service fallback guarantees functionality
   • Centralized error handling prevents crashes
   • Async/await wrapper catches rejections
